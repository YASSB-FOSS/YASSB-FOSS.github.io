Directives

directive.attributes

stable since 1.0.0

Shared attribute syntax of directives: quoted values, JSON options, LANG and USERNAME placeholders.

<!-- create-from-data-source="LANG/news.json" renderer="list" options="{"order":["b","a"],"limit":3}" -->
Options
options: JSON (object or array) written as is inside double or single quotes, anywhere in the directive.
Rules
Values end at the closing quote; LANG anywhere in the directive (options included) becomes the current language; USERNAME becomes config.username (the text "undefined" if unset); invalid options JSON is reported and ignored.
Errors
OPTIONS_INVALID_JSON
Related
config.username directive.create-from-data-source

directive.component

stable since 1.0.0

Inserts an HTML, SVG or Markdown fragment from the components folder, recursively.

<!-- component="site/header.html" -->
Options
The value is a path relative to src/app/components (workingDir.components); LANG and USERNAME are replaced (see directive.attributes).
Rules
Each component is processed on its own (its directives run with fileFullPath = the component file) before being inserted into the including file; components can nest; .md/.txt components are converted from Markdown; front matter of a component becomes { key } placeholders of the page; a missing file leaves the comment in place (removed by the minifier); more than 40 levels of nesting is reported as a cycle; the regex accepts one directive per line.
Errors
COMPONENT_NOT_FOUND COMPONENT_UNSUPPORTED_FORMAT COMPONENT_CYCLE
Related
content.front-matter content.markdown directive.attributes

directive.create-from-data-source

stable since 1.0.0

Renders a JSON data source with a renderer and inserts the resulting HTML.

<!-- create-from-data-source="people/team.json" renderer="peopleCards" options="{"limit":3}" -->
Options
renderer: name in customRenderers or a built-in renderer (default basicElement); options: JSON passed to the renderer as props.options.
Rules
One JSON file per directive, path relative to src/app/data-sources (sub-folders allowed); the file is parsed again for every directive, so renderers may mutate their data; the renderer receives source (parsed JSON) and sourcePath; every occurrence of the same directive text in the file is replaced; a missing file or name leaves the comment (removed by the minifier) and is reported; invalid JSON or a throwing renderer fail the build.
Errors
DATA_SOURCE_MISSING_NAME DATA_SOURCE_NOT_FOUND DATA_SOURCE_INVALID_JSON
Related
api.custom-renderers directive.attributes renderer.basicElement

directive.generate-from-files

stable since 1.0.0

Generates one page per Markdown/text file from a template in pages-to-generate.

In src/app/pages-to-generate/blog/post.html: <h1>{ title }</h1> <!-- generate-from-files="blog" -->
Options
The value is a folder relative to src/app (workingDir.posts); USERNAME is replaced.
Rules
The directive must be in the template file itself, not in a component; .md and .txt files are read recursively; output is <out>/<template folder>/<file sub-folder>/<slug>.html with slug = front matter slug, else the title in kebab-case, else the file name; front matter placeholders are replaced at once and again in post-processing; generated pages then go through all directives; with i18n only templates inside a language folder (pages-to-generate/en/...) are translated, so a multi-language blog needs one template per language.
Errors
TEMPLATE_NO_DIRECTIVE TEMPLATE_SOURCE_NOT_FOUND MARKDOWN_EMPTY
Related
content.markdown content.front-matter

directive.url-to

stable since 1.0.0

Replaced by the absolute URL of the output file whose path contains a fragment.

<a href="{{ url-to="about" }}">  <a href="{{ url-to="blog-post#comments" options="{"warning":false}" }}">
Options
#anchor is kept; options="{"warning":false}" silences the ambiguity warning.
Rules
The fragment is matched case-insensitively against every URL of the output (also as kebab-case and snake_case); with several matches the file closest to the current page wins, ties go to an index.html; only files written by the current build are visible (files left in the output by an earlier build are not, so a build into a folder that was not emptied resolves like one into an empty folder); with i18n only pages of languages already built are visible; the host (siteHost or the internal one) is stripped, so the result is root-relative (/en/about/index.html); no match inserts nothing and suggests the closest URL.
Errors
URL_TO_EMPTY URL_TO_NOT_FOUND URL_TO_AMBIGUOUS
Related
behaviour.sitemap config.siteHost

Built-in renderers

renderer.basicElement

stable since 1.0.0

Built-in renderer: one element per item, with item.description as content.

<ul><!-- create-from-data-source="items.json" renderer="basicElement" options="{"tag":"li","attributes":{"class":"x"}}" --></ul>
Options
tag (default span); attributes: object applied to every element (true → bare attribute, false → omitted, arrays joined with spaces).
Rules
source is an array of { description } or, with i18n, { description: { <lang>: text } }; descriptions are inserted as HTML; used as fallback when a directive has no or an unknown renderer.
Related
directive.create-from-data-source

renderer.liDateDescription

stable since 1.0.0

Built-in renderer: <li><u>date</u>: description</li> per item, with localized dates.

<ul><!-- create-from-data-source="timeline.json" renderer="liDateDescription" --></ul>
Options
none
Rules
date is { start, end } with YYYY, YYYY/MM or YYYY/MM/DD (formatted in the current language: "March 2020", "March 5, 2020"), end "-" means present (<span data-t="PRESENT">, translated by i18n), or { raw } inserted as is; description as in basicElement.
Related

cli.watch

stable since 1.0.0

yassb watch: build, serve with live reload, rebuild on every change.

yassb watch [--port <n>] [--clean] [--strict] [--fresh]
Options
--port <n>: dev server port (default devServerPort or 3000; 0 = any free port); --clean: empty the output before the first build; --strict: passed to every build; --fresh: every build in a new process, without warm builds and verification.
Rules
The whole project is watched except the output folder, node_modules, .git and editor temp files; events that do not change a file are ignored (its ctime is unchanged and not recent: Bun reports such events on the source of a copy); builds run in child processes started ahead of time (Node, the engine and the site's packages loaded before the next change), and every build loads the configuration and site code again; a change to site code, the configuration or a file outside src is built by a new process, so config, renderers, directives, package.json and tsconfig changes are always picked up; a content change is built by the warm process that built last (faster, reloads at once), then verified: a process that never built rebuilds the same steps into a shadow folder next to the output (.<out name>.yassb-verify, deleted when watch stops), files that differ are copied into the output and the browser refreshes again (CSS swapped if only stylesheets differ), and that process becomes the warm one; a change during a verification cancels it and its steps are verified with the next one; the afterBuild hook also runs for verification builds, with out set to the shadow folder; a stylesheet change only recompiles styles (CSS swapped without reload), a change to a file used only by the scripts only rebundles them, other changes rebuild pages (and styles with a custom stylesParser), changes outside src or to site code rebuild everything; errors are printed and shown in the browser overlay while the server keeps running; changes during a build are queued into one more build; pages are not minified.
Errors
BUILD_CRASHED
Related
behaviour.dev-server behaviour.live-reload behaviour.site-code

i18n.translation

stable since 1.0.0

Translates marked text and attributes of every page into each language.

<h1 data-t="HOME.TITLE">Welcome</h1>  <p data-t>Welcome</p>  <img data-attr-t alt-t="HOME.LOGO">  <p data-t="GREET" data-t-interpolate>
Options
config.i18n.allowHtml inserts translations as HTML; data-t-interpolate / data-attr-t-interpolate replace {{KEY}} placeholders.
Rules
Runs after all directives, so renderer output is translated; data-t with no value uses the element text as key; any <attr>-t on an element with data-attr-t sets <attr>; keys are flat ("HOME.TITLE") or nested objects; a missing key keeps the original text; translation attributes are removed; only translated elements are rewritten, the rest of the page is kept byte for byte; translations are escaped as text unless allowHtml; pages outside language folders are not translated.
Errors
I18N_MISSING_KEY I18N_INVALID_FILE I18N_UNCLOSED_ELEMENT
Related

Extension API

api.custom-directives

stable since 1.0.0

Site-defined directives: classes with a static regex whose init() rewrites the HTML.

class YearDirective implements YassbDirective { static regex = /<!--\s*current-year\s*-->/g; constructor(private args: YassbDirectiveProps) {} init() { return { html: ..., data: {} }; } }  then customDirectives: [YearDirective]
Options
none (registered with config.customDirectives)
Rules
Built-in directives run first, then custom ones in the order of customDirectives; init() is called once per regex match with the HTML updated by the previous call, so directives must be idempotent; components are processed before the page that includes them (fileFullPath is the component in src, then the page in out); data values become { key } placeholders; YassbBaseDirective copies the props to protected fields; an exception or a missing html fails the build with the directive location.
Errors
DIRECTIVE_NO_REGEX DIRECTIVE_FAILED
Related
config.customDirectives directive.component

Props: source, sourcePath, options, lang, currentFilePath, config, frontMatterStore.
Rules
A renderer returns a string and must not write files; without renderer attribute basicElement is used (warning), with an unknown name basicElement is used (error); a throwing renderer fails the build with the directive location and inserts nothing; emitted <span data-t="KEY"> is translated afterwards.

RENDERER_MISSING RENDERER_NOT_FOUND RENDERER_FAILED

behaviour.dev-server

stable since 1.0.0

Development server of watch and serve (not for production).

http://localhost:3000/  →  <out>/<first language>/index.html
Options
config.devServerPort, --port.
Rules
/<lang>/... → <out>/<lang>/...; other paths → <out>/<first language>/..., then <out>/...; folders redirect to a trailing slash and serve index.html; not found → the home page with status 200; Range requests supported; files carry an ETag (size and modification time) and must be revalidated, so unchanged files are answered with 304 and not downloaded again; if the port is busy the next ones are tried.
Related

behaviour.diagnostics

stable since 2.0.0

Every problem is reported with a stable code, file, line and hint.

error DATA_SOURCE_NOT_FOUND src/app/pages/index.html:12 …  /  yassb build --json  /  yassb docs diagnostics
Options
--json on build and check; config.strict.
Rules
Pages are reported on their source file (pages/, the template, or the Markdown file); the same problem reported for a component and its page is kept once; fatal problems (exceptions in site code, invalid JSON, config errors) exit 1, others only with strict; missing translations are collected and summarised.
Related
cli.check config.strict

behaviour.live-reload

stable since 2.0.0

In watch mode pages reload by themselves and show build errors.

automatic in yassb watch (script injected before </body>, events on /__yassb/events)
Options
none
Rules
Reload after a page or script rebuild; CSS swapped without reload after a styles-only rebuild; a badge while rebuilding; an overlay lists the errors of the last build (code, file:line, message, hint), hidden when fixed; status also at /__yassb/status; reloads when the watch process restarts.
Related

behaviour.output-lock

stable since 2.0.0

Only one YASSB process at a time writes an output folder; a second one stops with a clear message.

Running `yassb build` while `yassb watch` serves the same folder → error OUTPUT_LOCKED naming the other process.
Options
none (use --out <dir> to build somewhere else)
Rules
build and check hold the lock during the build; watch holds it for its whole session and its rebuilds share it; the lock file is in the system temporary folder (never in the output); a lock left by a process that no longer exists (crash, kill -9) is taken over (the message names the lock file to delete if its process id was reused); different output folders never conflict; the second process exits with code 1 without writing anything.
Errors
OUTPUT_LOCKED
Related
cli.build cli.watch cli.check

behaviour.pipeline

stable since 1.0.0

The fixed order in which a build processes a site.

yassb build, yassb watch, or programmatically: await runBuild({ strict: true }) in the project folder.
Options
BuildOptions: watchMode, steps { html, styles, scripts }, strict, clean, outDir.
Rules
config → beforeBuild → assets copy → scripts bundling starts → generate-from-files → for each language: copy pages (all files of pages/), list output files (url-to, sitemap), then per HTML page: components → front matter → built-in directives → custom directives → translation → post-processing of every HTML file of the output → styles → scripts written → afterBuild; directives left in a page after processing are reported.
Errors
DIRECTIVE_UNPROCESSED
Related
behaviour.post-processing api.custom-directives i18n.translation

behaviour.post-processing

stable since 1.0.0

Last step for every HTML file of the output.

automatic; customize with config.postProcessors and config.htmlMinificationOptions
Options
none
Rules
For every .html/.htm in the output (assets included): { key } placeholders → postProcessors in order → minification in build, or in watch the live-reload script before </body> and removal of the Content-Security-Policy meta; runs after translation.

behaviour.site-code

stable since 1.0.0

Configuration and site code can be TypeScript, TSX or JavaScript.

config/default.ts importing builder/renderers.tsx
Options
The site's tsconfig.json (jsx, decorators, class fields).
Rules
Under Node each file is compiled on its own to CommonJS with esbuild (like ts-node --transpile-only): __dirname, relative imports and require work as in Node; no type checking; stack traces point to the TS lines; Bun runs TypeScript natively; a syntax error is reported with file and line.

behaviour.sitemap

stable since 1.0.0

sitemap.xml lists every file of the output; it is also the list url-to searches.

<out>/sitemap.xml with <loc>https://example.com/en/index.html</loc> entries
Options
config.siteHost (keeps the file and is the host of the URLs), config.sitemap: false (never written).
Rules
Regenerated before each language is processed; includes assets and every file written by the current build (not files left in the output by an earlier one); without siteHost the host is http://fake.host/ and the file is deleted at the end of the build (after post-processing); post processors may replace it.
