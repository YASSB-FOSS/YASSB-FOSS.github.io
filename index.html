The mental model

One file per job. Readable at a glance.

Data lives in JSON, the page declares what it shows, a typed function renders it. No template language to learn, no magic to reverse-engineer: you, your teammates and your coding agent can read every page and know where everything comes from.

1Data

Content in plain JSON.

Content lives in JSON or Markdown files, apart from markup and code. Change the data, and no page needs editing.

2UI

Simple HTML, made of components.

Pages are plain HTML. Write a block once as a component and reuse it anywhere. A directive marks where data goes: it names the data file and the renderer that turns it into HTML.

UIsrc/app/pages/index.html

<main>
  <!-- component="site/header.html" -->
  <h1 data-t="HOME.TITLE">Talks</h1>
  <ul class="talks">
    <!-- create-from-data-source="talks.json" renderer="talkList" options="{"limit":3}" -->
  </ul>
</main>

3Logic

TypeScript, run at build time.

A renderer is a typed function: it gets the data and options from the directive and returns HTML, with any loop or condition you need. Custom directives are TypeScript too. All of it runs at build time: visitors get static HTML.

Logicbuilder/renderers.ts

import { RendererProps } from 'yassb-web';

type Talk = { title: string; date: string; place: string };

export function talkList({ source, options }:
  RendererProps<Talk[], { limit?: number }>) {
  return source
    .slice(0, options?.limit)
    .map(t => t.place === 'Online'
      ? `<li>${t.title} · <a href="/live">watch live</a></li>`
      : `<li>${t.title} · ${t.place}</li>`)
    .join('');
}

Developer experience

A watch mode you can trust.

Save a file, see the page. Change a renderer, the config, even package.json: picked up, every time.

1Fast, then verified.
A warm process rebuilds a content change at once, then a clean one checks it gives the same output as yassb build. Change your code or the config and a new process picks it up.
2Only what changed.
A stylesheet edit swaps the CSS without reloading; a script edit only rebundles the scripts.
3Errors in the page, not in a log.
If your code throws, the server stays up and the browser shows what broke, with file and line.
4TypeScript with zero setup.
Config, renderers and directives in TS or TSX, compiled by esbuild. No ts-node, no build step.
